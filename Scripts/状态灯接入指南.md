# Stream Dock 状态灯接入指南（多 Agent 通用）

**读者**：任何 AI coding agent。你的任务：为你所服务的 agent 接入一块 Stream Dock 键面状态灯，让它实时显示该 agent 的工作状态。

**参照实现**：`com.zcode.status.sdPlugin`（ZCode 状态灯，2026-10-16 真机闭环；2026-10-22 起为鲸鱼娘帧动画）。本模板目录 = 干净无运行时数据的源码，直接以它为起点。

**宿主通用能力**（插件协议、图像契约、键位、部署排障）见 [`../AGENT-GUIDE.md`](../AGENT-GUIDE.md)；本文只覆盖状态灯这条最短路径。

---

## 0. 架构 30 秒

```
agent hooks(生命周期事件) → hook 脚本原子写 state.json → OpenDeck 插件页(宿主每秒推拍驱动)读取 → 状态变化才重绘上屏
```

- 宿主 OpenDeck（macOS 自研 Stream Dock 管理器）以无头 WKWebView 常驻运行每个 HTML 家族插件，插件页定时器由**宿主推拍**驱动（页面自持定时器在隐藏页面会被 WebKit 冻毙，宿主已解决，与你无关）。
- 渲染侧（`index.html` + `whale.js`）**零改动**。你的全部工作 = **拷贝模板插件 + 改名改 UUID + 写你自己的 hook 脚本 + 在你的 agent 配置里挂 hooks**。
- 为什么每个 agent 一份插件拷贝而不是共用一个插件：每份插件根目录独立 → `state.json` 天然隔离，渲染代码无需任何参数化；代价是每个 agent 占一个键位（设备 15 键）。

## 1. 硬契约（唯一不可协商的部分）

### 1.1 state.json

**位置**：你的插件根目录下，文件名必须是 `state.json`（宿主文件桥 `opendeckReadFile` 有沙盒校验：只允许读插件根内的相对路径，越界即拒）。

**格式**：

```json
{"state": "working", "updatedAt": 1760000000000}
```

- `state` ∈ `ready | working | asking | permission | error | done`（语义见 §2）
- `updatedAt` = epoch **毫秒**
- **原子写**：先写 `state.json.tmp` 再 `os.replace()`（或等价的原子替换），读侧永不看到半截 JSON
- **免心跳**：updatedAt 超 30 分钟未更新，插件自动显示 idle 灰●。你只在状态迁移时写盘，无需定时器

### 1.2 hook 脚本铁律

hook 由 agent 同步调用，**阻塞主流程**。四条铁律，违反任何一条都会拖慢甚至弄坏用户的 agent：

1. **亚 100ms 退出**：只做「读 stdin → 写一个小 JSON」这一件事
2. **exit 0，零 stdout/stderr**：任何输出都可能被 agent 当作异常
3. **所有异常静默吞掉**：状态灯绝不反噬主流程——灯挂了无所谓，agent 不能挂
4. **不确定的事件映射宁可不写**：错映射比少映射更糟（如把高频事件映射到 asking 会狂闪）

## 2. 状态语义表

| state | 键面（鲸鱼娘） | 语义 | 写盘时机 |
|---|---|---|---|
| `ready` | 绿色开心 | 会话启动就绪 | 会话启动事件 |
| `working` | 蓝色敲键盘 | 执行中 | 用户提交输入、工具开始/结束 |
| `asking` | 黄色**招手 + 脉冲** | 结构化向用户提问 | 发起提问工具时（用户作答后由下一事件自然切走） |
| `permission` | 黄色举手 + ? | 等待权限/授权 | 请求授权事件 |
| `error` | 红色 X 眼 + 抖动 | 工具执行失败 | 失败事件（或从工具结果 payload 检出失败） |
| `done` | 绿色开心 + 星星 | 回合完成待输入 | 回合结束事件 |

- `idle` 灰色打盹由插件端判超时，**不归你写**。
- 动画节拍由页面回传给宿主的 `nextInterval` 自适应（working/asking 200ms，permission 300ms，error/done 250ms，idle 450ms），你只管写 `state: "asking"`。

**画布是 112×112**（不是 100×100）；透明区域由宿主合成到键面底色后下发。

## 3. 执行步骤

以下 `<标识>` 用你的 agent 名（如 `claude`、`codex`），只允许小写字母数字连字符。

**Step 1 拷贝模板到 OpenDeck 插件目录**（该目录只在 OpenDeck 启动时扫描）：

```bash
cp -R "/Users/yorkli/Downloads/shortcut general/mirabox/Scripts/com.zcode.status.sdPlugin" \
      "$HOME/Library/Application Support/OpenDeck/plugins/com.<标识>.status.sdPlugin"
```

**Step 2 改 manifest.json**（三处全换成新身份，缺一可能与 ZCode 灯互相串扰）：

- 文件夹名已换（Step 1）
- `"Name"`：如 `"Claude 状态灯"`
- `"Actions"[0]."UUID"`：`com.<标识>.status.light`
- 可选：`"Actions"[0]."ActivateAppBundleID"` 填你的 app bundle id（如 `"com.anthropic.claudefordesktop"`）→ 用户按状态灯键即把你的窗口置前，见 §7

**Step 3 `index.html` 与 `whale.js` 一行都不动。**（Step 1 整目录拷贝已包含 `whale.js`；只拷 `index.html` 会白屏。）

**Step 4 改写 hook.py 的事件映射**：只需替换 `EVENT_TO_STATE` 字典的**键**（你 agent 的事件名）与 `ASKING_TOOL`（你 agent 的结构化提问工具名）。映射方法见 §4。

**Step 5 在你的 agent 配置里挂 hooks**：每个要监听的事件配一条命令：

```
python3 /Users/yorkli/Library/Application Support/OpenDeck/plugins/com.<标识>.status.sdPlugin/hook.py
```

（**绝对路径**，含空格务必加引号。）

配置格式参照 ZCode 的形状（`~/.zcode/cli/config.json` 顶层 `hooks` 块：`events → [{hooks: [{type: "command", command: "..."}]}]`，`timeoutMs: 2000`）；**你的 agent 配置文件位置与格式以你自己的官方文档为准**。

**Step 6 重启 OpenDeck**（菜单栏退出再启动），确认插件列表出现新插件。

**Step 7 手动自测写盘链路**：

```bash
echo '{"hook_event_name":"<你的working事件名>"}' | python3 "<插件根>/hook.py" && cat "<插件根>/state.json"
```

应输出 `{"state": "working", ...}`。

**Step 8 请用户在 OpenDeck 界面把新动作绑到一个空闲键位**（此步人工，agent 到此为止；不要手改 OpenDeck 的 config/settings——app 不监听磁盘变化，下一次变更会用内存快照整份覆盖）。

**Step 9 真机验收**（与用户对表）：发消息转蓝色敲键盘 → 提问黄色招手 → 回复后回蓝 → 完成绿色开心 → 静置 30 分钟灰色打盹。运行中的观测面：插件页每 60s 打一条 `alive state=... ctx=1` 日志：

```bash
log stream --level info --predicate 'subsystem == "opendeck"'
```

（OpenDeck 没有插件日志面板；`--level info` 必须带，`log show` 默认不含 info 历史。）

## 4. 事件映射怎么找

逐条查你自己的 hooks 官方文档回答：

1. 会话启动事件？→ `ready`
2. 用户提交输入事件？→ `working`
3. 工具调用前/后事件？→ `working`（后置更准：后置失败事件还能顺带判 `error`）
4. 结构化提问有专用事件，或可在工具前置事件里按工具名识别？→ `asking`
5. 权限/授权等待有事件吗？→ `permission`
6. 工具失败怎么检出？（专用失败事件？还是后置事件 payload 里的 `is_error` 类字段？）
7. 回合结束事件？→ `done`

**ZCode 已验证对照（可直接抄进你的思考）**：

| ZCode 事件 | 状态 |
|---|---|
| `SessionStart` | ready |
| `UserPromptSubmit` / `PostToolUse` | working |
| `PermissionRequest` | permission |
| `PostToolUseFailure` | error |
| `Stop` | done |
| `PreToolUse` 且 `tool_name == "AskUserQuestion"` | asking |

**Claude Code 粗对照（未真机验证，务必核对官方文档后再写死）**：`SessionStart`→ready；`UserPromptSubmit`/`PostToolUse`→working；`Notification`（等待授权时触发）→permission；`Stop`→done；`PreToolUse` 且工具为 `AskUserQuestion`→asking；工具失败无专用事件，需在 `PostToolUse` 的 payload 中判 `is_error`（此时 hook.py 需小幅扩展解析，仍守铁律）。

注意 stdin payload 结构各 agent 不同（如事件名字段可能叫 `hook_event_name` 或别的），hook.py 解析字段名按你的 agent 实际 payload 调整。

## 5. 已知边界与红线

**已知边界（v1 接受，勿自行扩大改动面）**：

- hooks 配置一般在**会话启动时加载**：挂好后需新开会话才生效
- 同一 agent 多会话并发时，后写覆盖先写（灯显示"最后一个会话"的状态）
- 纯文本提问没有 hook 事件可挂 → 不触发 asking（只有结构化提问工具可以）
- 渲染侧对未知 `state` 值按 idle 处理——映射写错最多显示异常，不会崩

**红线**：

- 不改 OpenDeck 宿主、不改 `index.html` / `whale.js`、不动 ZCode 已有的 `com.zcode.status.sdPlugin`
- hook 脚本里不做网络请求、不起子进程链、不轮询
- 不要用守护进程常驻轮询 agent 内部状态来替代 hooks——有事才写盘，没事不碰盘
- OpenDeck 每次配置/参数变更都会用内存快照整份覆盖盘上文件：**永远不要在 app 运行时手改 settings 或 config**

## 7. 可选增强：按键置前本 agent

在 manifest 的 action 里声明宿主 app 的 bundle id：

```json
"ActivateAppBundleID": "com.example.youragent"
```

效果：用户**按下状态灯键（抬起沿）**，宿主 OpenDeck 直接激活你所属的桌面 app——运行中=窗口置前，未运行=启动。ZCode 灯已声明 `dev.zcode.app`。

- bundle id 查法：`defaults read /Applications/<App>.app/Contents/Info.plist CFBundleIdentifier`
- 走 LaunchServices，无需任何系统权限；目标未安装只记日志，无副作用
- 这是宿主通用机制，与状态逻辑完全解耦，不加也不影响灯的任何功能

# Toggle Monitor — 动效键面交付说明

槽位 1 · OpenDeck · Stream Dock 293V3 · 112 × 112

---

## 1. 这个键实际在做什么

槽位 1 的动作是 macOS 快捷指令 **Toggle Monitor**，其内容不是“显示器开关”，而是：

```
/Users/yorkli/bin/lg-toggle.sh
  ├─ 读 ~/.cache/lg_input（mac / pc）
  ├─ mac → m1ddc set input-alt 144   （DP / Mac → HDMI1 / PC）
  └─ pc  → m1ddc set input-alt 208   （HDMI1 / PC → DP / Mac）
```

因此动效母题定为 **“信号从一台机器搬到另一台”**，而不是电源开关：

- **静息态**回答“现在谁在屏”：哪枚源芯片亮、屏幕内容用哪套桌面语言、LED 什么颜色。
- **按压态**把这次搬家演出来：信号球离开旧源、越过底座、落进新源；显示器先失步、再点亮。
- **失败态**（快捷指令没生效）回退并闪一次红灯，不静默撒谎。

状态文件是唯一事实来源；图标只是它的可视化。

## 2. 版式

```
112 × 112（安全边距 8）

        ┌──────────────────────┐
        │   显示器 64×44 @24,20 │  ← 机身 #2A3140→#11151D，屏 57×37
        │   ┌────────────────┐  │
        │   │ 桌面内容       │  │  ← 菜单栏/任务栏 + 两扇窗 + 光标
        │   └────────────────┘ ●│  ← 状态灯 3px，颜色 = 当前源
        └──────────┬───────────┘
                   │ 支架
            ╭──────┴──────╮
            │             │
        ╭───┴───╮     ╭───┴───╮
        │   M   │     │   P   │   ← 源芯片 26×16 @19,84 / @67,84
        ╰───────╯     ╰───────╯
```

- 左芯片固定为 Mac（冷蓝 `#4DA3FF`），右芯片固定为 PC（暖橙 `#FFA94D`）。
- 芯片字母用 **单线 M / P**，不用笔记本/塔机剪影：26×16 的芯片里，任何设备剪影都会读成手机或显示器；字母在 112px 上零歧义，也与用户口中的 Mac / PC 对齐。
- 屏幕内容用桌面语言区分两源：Mac 是顶部菜单栏，PC 是底部任务栏。颜色 + 芯片 + LED 三重编码，缩小到实际键面仍能读。
- 无标题文字。标题与底图在动效键上被有意忽略。

## 3. 状态机

```
                 ┌──────────────┐
   启动/换页 ───▶│  idle(source)│◀──── 对账一致
                 └──────┬───────┘
                        │ 按下
                        ▼
              ┌──────────────────┐
              │ transition 12 帧 │  ← 乐观动画，不等脚本
              └──────┬───────────┘
                     │ 1.0s
          ┌──────────┴───────────┐
          │ 读 ~/.cache/lg_input │
          └──────┬───────────────┘
       一致 ─────┤ 3s 内不一致
                 ▼
          ┌─────────────┐
          │ revert 12 帧 │  ← 反向迁移 + LED 红闪
          └─────────────┘
```

- 按下后立刻起动画（手感优先），同时照常执行快捷指令。
- 动画结束后读状态文件：对上即确认；3 秒仍未变则反向播放一次回退动画。
- 平时每 1.5s 轮询一次状态文件，外部切换（显示器摇杆、其它触发器）也会同步。
- 换页离开再回来会重新读盘，不显示离开前的旧状态。
- 静息呼吸每 8s 一次，6fps × 6 帧；系统“减弱动态效果”开启时自动关闭。

## 4. 12 帧分镜（12fps / 1.0s）

| 帧 | 时间 | 节拍 | 画面 |
|---:|---:|---|---|
| 00 | 0 ms | 按压 | 源芯片压到 0.93×；屏幕内容反向偏 1px，做预备。 |
| 01 | 83 ms | 起跳 | 信号球 1.25× 充电，仍在源点；旧链路开始退亮。 |
| 02 | 167 ms | 入轨 | 迁移进度 0.16，信号球出现三层拖尾。 |
| 03 | 250 ms | 中段 | 进度 0.50；旧芯片 0.60，新芯片仍暗。 |
| 04 | 333 ms | 接近 | 进度 0.84；屏幕压暗 22%，准备失步。 |
| 05 | 417 ms | 落位 / 失步 | 1.4px 过冲；冲击环 3.5 → 8；屏幕切黑，只留一条扫描线。 |
| 06 | 500 ms | 点亮 | 新画面 55% 亮度、1.05× 缩放、源色闪光 0.38；新链路画到 90%。 |
| 07 | 583 ms | 稳定 | 画面 100%，LED 完成换色，冲击环收至 0.10。 |
| 08 | 667 ms | 扫光起 | 白色高光带从屏幕左侧进入（10%）。 |
| 09 | 750 ms | 扫光过 | 高光带 20%，扫过屏幕右半。 |
| 10 | 833 ms | 收 | 高光带离场，所有元素归位。 |
| 11 | 917 ms | 静息 | 保持到 1.0s，随后进入静息呼吸。 |

### 节奏依据

- **单一主角**：只有信号球在长距离移动，其它元素按因果延迟响应（球落位后屏幕才切）。
- **预备 / 过冲 / 回稳**：0.93× 按压 → 1.18× 落位 → 1.0× 稳定。
- **物理依据**：真实显示器切输入源会黑屏约 0.2–0.5s，所以第 5 帧“失步”不是装饰，是把硬件的真实延迟画出来。1.0s 的总时长因此不是“UI 动画太慢”，而是与输入握手同量级。
- **12fps 是主动选择**：这是动画的“一拍二”。关键姿态清晰、拖尾可读，避免小屏上 60fps 的运动模糊；同时把 USB HID 的写入预算压在 6 帧/秒以下（过渡期 12 帧/秒，仅 1 秒）。

## 5. 设计 token

| 项 | 值 |
|---|---|
| 画布 / 安全区 | 112 × 112 / 8 px |
| 显示器机身 | 64 × 44 @ (24, 20)，r7 |
| 屏幕 | 57 × 37 @ (27.5, 23.5)，r4 |
| 支架 | 颈 4 × 6，底座 22 × 3 @ (45, 69) |
| 源芯片 | 26 × 16，r5，@ (19, 84) / (67, 84) |
| 信号球 | r 2.0（1.18× 落位 ≈ r 2.36） |
| 迁移路径 | 二次贝塞尔 (32,84) → 控制 (56,77.5) → (80,84) |
| 迁移曲线 | `cubic-bezier(.77, 0, .175, 1)`，采样到 0.16 / 0.50 / 0.84 |
| 点亮曲线 | `cubic-bezier(.23, 1, .32, 1)`，1.05× 过冲为手调 |
| 色彩 | Mac `#4DA3FF`，PC `#FFA94D`，底 `#04060A`，机身 `#2A3140→#11151D` |
| 过渡 | 12 帧 × 83.3 ms = 1.0 s |
| 静息呼吸 | 6 帧 × 166.7 ms，每 8 s |
| JPEG | ≈ 3.9 KB / 帧（设备上限 10,240 B） |
| 设备方向 | 渲染后预旋转 180°；UI 镜像再转回正立 |

## 9. 边界

- 同一时刻只服务一颗键；动效状态是全局的（只有一路显示器输入）。若在编辑器里给第二颗键也打开动效，动画会挂到最后挂载的那颗。
- 12fps 由 `Timer` 驱动，不依赖网页 `requestAnimationFrame`；页面隐藏/后台不会冻结。
- 回退判定依赖状态文件。若用户手动改了显示器输入但没有更新 `~/.cache/lg_input`，图标会在下一次轮询时跟随文件，而不是跟随真实硬件——这是现有 `lg-toggle.sh` 的契约。
